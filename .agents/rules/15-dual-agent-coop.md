# 15 — 双 Agent 协同与 HUD 交接

## 适用范围

仅当环境实际提供 Agent HUD 的会话互发能力（`mcp__agent-hud__list_sessions`、`mcp__agent-hud__send_message`）时适用。单 Agent 环境不得声称已派发对方窗口或完成独立复核。本规则默认不激活：未收到短码或协作指令时按单兵执行。

## 1. 模式矩阵与短码

| 短码 | 模式 | 当前窗口 | 对方窗口 |
|---|---|---|---|
| #mc | MAKER-CHECKER | CODER（写+提交） | AUDITOR（只读盲审） |
| #ae | ARCH-EDITOR | ARCHITECT（只读定稿） | EDITOR（按稿落盘） |
| #tdd | TDD | TESTER（独占 tests/） | IMPLEMENTER（写业务） |
| #ss | SCOUT-STRIKER | SCOUT（压缩坐标） | STRIKER（干净会话改码） |
| #fix | DIAGNOSE | STUCK（停手） | DIAGNOSTICIAN（盲测排障） |

- 短码后加 `-r` 立即互换双方角色。
- 收到 `#co` 时先输出模式选单并标注推荐项，等用户回数字后再启动；此阶段不改代码、不发 MCP。
- 审计方只依据实际差异、契约文档与静态/测试工具结论，不采信编码方口头辩解。

## 2. 令牌环写锁

- 同一时刻仅一个 Agent 持同一目录写权限；非持锁方只读，不改业务源码、不提提交。
- 并发按目录划分时（如 TDD 的测试目录与业务目录）必须以显式路径提交，禁止无路径的全量暂存。
- 未与对方确认写锁前，不得并发修改同一文件。

## 3. 交接消息

- 单回合只发 1 条合并消息：本地检查、测试与提交全部结束后再投递。
- 消息体只带坐标与摘要，不贴大段代码：`路径:起始行-结束行` 加 3–5 行原始报错。
- 纯状态同步写入规则 07 的进度账本，不占用对方队列。
- 默认排队投递；仅当用户明确要求插话时才用 steer。
- 模板见第 5 节。

## 4. 熔断与轮次

轮次上限与阻断分歧的处置以规则 08 §3 为准，本规则不另行定义。补充执行口径：同一报错连续 2 次修复未通过，立即停手转 DIAGNOSE，只发最小复现命令、原始日志与相关坐标，不附带自己前两次的猜想，避免污染诊断视角。

## 5. 交接模板

```text
[HUD-HANDOFF]
MODE: <模式名>
YOUR_ROLE: <对方角色名>
BRANCH_COMMIT: <分支 @ 短 hash 或状态>
FILES_COORDS:
  - <路径:起始行-结束行> (简述)
CONTRACT_REF: <契约文档 | 无>
CHECK_RESULT: <已跑命令及结果，或 3-5 行原始报错>
ACTION_REQUIRED: <1-2 项明确动作；审计回传标明 PASS 或 P0/P1 清单及当前轮次>
```

## 6. Git 与凭据

提交、推送、分支与合并只经规则 14 与 git-vault 网关，本规则不定义第二条 Git 通道，也不规定凭据来源。

## 7. 上下文水位

上下文占用接近或超过 70%、或生成明显变慢时，先完成当前原子提交，再把现场写入规则 07 的进度账本并请人类开新会话；不得带着高水位上下文继续互发。
